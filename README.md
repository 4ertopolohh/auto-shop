# Крутящий момент

Локальный демонстрационный интернет-магазин автозапчастей: React 19, Vite, TypeScript strict, SCSS Modules; Django 5.2, Poetry, SQLite.

## Обычный запуск

В двух терминалах из папки проекта:

```powershell
cd backend
poetry run python manage.py runserver
```

```powershell
cd frontend
npm run dev
```

Витрина: http://127.0.0.1:5173 . Админка: http://127.0.0.1:8000/admin/ . В локальной рабочей папке среда уже подготовлена, база создана и наполнена.

Логин `admin`; случайный пароль записан в `backend/.local/admin-access.txt`. Файл, секреты и SQLite исключены из Git. Пароль не опубликован в репозитории. Сброс: `poetry run python manage.py changepassword admin`.

## Первая установка на другом компьютере

Нужны Python 3.12+, Poetry 2, Node.js 22.12+ (проверено на Node 24).

```powershell
cd backend
poetry install
poetry run python manage.py migrate
poetry run python manage.py seed_demo
poetry run python manage.py create_demo_admin
cd ../frontend
npm ci
```

Локальные ключи Django и Fernet создаются автоматически при первом запуске. `seed_demo` не стирает и не перезаписывает существующие товары; повторный запуск не создаёт дубликатов. В каталоге 18 товаров, 6 категорий, галереи, характеристики, артикулы, применимость и наличие.

## Возможности

- Главная с подбором по марке и модели, интерактивной схемой узлов автомобиля и категориями.
- Каталог: поиск по названию/артикулу/OEM/бренду, фильтры, серверная сортировка и пагинация.
- Отдельные страницы товаров с переключением изображений, характеристиками, применимостью и связанными товарами.
- Корзина с количеством, оформлением, выбором СДЭК и демонстрационной оплатой ЮKassa. Проверяемые результаты: успех, отказ, повтор, отмена.
- Русская Django Admin: категории, товары, inline-галереи, цены, наличие, настройки витрины/SEO/интеграций, заказы и журнал.
- Импорт `.xlsx` из списка товаров: шаблон, ZIP-фотографии, предпросмотр, ошибки, подтверждение. Обновление по артикулу. JSON-колонки характеристик и совместимости. До 2000 строк, XLSX до 5 МБ, ZIP до 30 МБ (60 МБ распакованных изображений). Товарные фотографии из загрузки декодируются и пересохраняются WebP; ссылки из таблицы не скачиваются.
- Настройки SEO: title/description, canonical, управление индексацией, `/robots.txt`, `/sitemap.xml`; метатеги товаров. Демо закрыто от индексации по умолчанию.
- Lazy-маршруты и изображения, skeleton без градиентов, адаптив, фокус и reduced motion.

## Политика демонстрационной версии

Поля контактов заполнены вымышленными значениями и доступны только для чтения. Сетевая форма заказа отправляет только ID товаров, количества, код демонстрационного пункта/способа доставки и случайный ключ повторного запроса. Сервер отвергает контактные поля и определяет цены самостоятельно. Корзина находится только в памяти вкладки. В заказах хранятся только вымышленные имя, телефон, email и адрес. Банковские реквизиты не вводятся и не сохраняются. Никакие внешние скрипты аналитики не подключены.

Локальный тестовый режим включён в **Настройки сайта → Локальный тестовый режим**. Он использует MockProvider без сетевых вызовов. Выключение режима останавливает демонстрационные операции; пустые ключи не считаются рабочими. При `SHOP_ENV` отличном от `local` MockProvider недоступен и сохранение включённого тестового режима запрещено. Авторизация и CSRF остаются включёнными.

`DEMO_SITE=True` — фиксированная политика этой сборки, не переключатель в админке. Внешние адаптеры ЮKassa (создание/проверка платежа), СДЭК (OAuth, ПВЗ, тариф, отправление) подготовлены отдельно и жёстко заблокированы в демоверсии. Секреты в админке шифруются Fernet, сохраняются без обратного показа и не попадают в API.

**Коммерческий запуск — отдельная работа:** реальные учётные записи и договоры, техническая база применимости, фискальные чеки, подтверждение оплаты сервером, идемпотентная постановка отправления, обработка возвратов, политика персональных данных/согласия, HTTPS, резервные копии, production-сервер и пререндеринг/SSR индексируемых страниц. Публичный запуск Django dev server не предусмотрен. Внешние адаптеры без ключей и реальных провайдеров не проходили интеграционные испытания.

При `SHOP_ENV=production` обязательны `DJANGO_SECRET_KEY`, `FIELD_ENCRYPTION_KEY`, `ALLOWED_HOSTS`; DEBUG отключён, cookies защищены, включён HTTPS redirect. Интеграции и прикладные настройки меняются из админки, инфраструктурные ключи — отдельно от базы. Демо не сохраняет IP и user-agent в прикладных моделях; стандартный dev-server выводит пути запросов в консоль.
